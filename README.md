# Vec и его модель роста, capacity в Rust

## Что такое `Vec<T>`

`Vec<T>` — это динамический массив из стандартной библиотеки Rust. Внутри он хранит три поля:

| Поле | Описание |
|------|----------|
| `ptr` | указатель на буфер в куче |
| `len` | количество **инициализированных** элементов |
| `cap` | количество элементов, под которые **выделена память** |

Ключевое различие: `len` — сколько элементов реально лежит, `cap` — сколько поместится без реаллокации.

```
[ 0 | 1 | 2 | ... | 499 | ? | ? | ... | ? ]
  └────── len = 500 ──────┘
  └────────────── cap = 1000 ─────────────┘
```

## Модель роста

При `push`, если `len == cap`, происходит **реаллокация**:

1. Выделяется новый буфер большего размера.
2. Все элементы **копируются** (перемещаются) в новый буфер.
3. Старый буфер освобождается.

Стандартная стратегия роста в Rust — **удвоение** (`cap * 2`, минимум 4/8 для мелких векторов). Это амортизирует стоимость: в среднем одна реаллокация на `O(1)` вставку, поэтому `push` имеет амортизированную сложность **O(1)**.

> Важно: конкретный коэффициент — деталь реализации, на него нельзя полагаться в коде. Гарантируется только амортизированная O(1).

## Разбор вашего примера

```rust
let size_of_vec = 1000;
let mut v = Vec::<usize>::with_capacity(size_of_vec); // одна аллокация на 1000

for i in 0..size_of_vec / 2 {  // 0..500
    v.push(i);                  // реаллокаций НЕТ — влезаем в cap
}

println!("cap: {}, len: {}", v.capacity(), v.len()); // cap: 1000, len: 500

v.shrink_to(600); // просим ужать cap до 600 (но не ниже len=500)

println!("cap: {}, len: {}", v.capacity(), v.len()); // cap: 600, len: 500
```

Почему `shrink_to(600)` даёт именно `600`, а не `500`:
- Метод уменьшает ёмкость **до `max(600, len)`**, но не ниже `len`.
- Поскольку `len = 500 < 600`, итог — `cap = 600`.
- Если бы вы вызвали `shrink_to(100)`, ёмкость стала бы `500` (нельзя ужать ниже `len`).

## `with_capacity` — избегаем реаллокаций

Если размер известен заранее — **всегда** используйте `with_capacity`:

```rust
// Плохо: возможны несколько реаллокаций (4 → 8 → 16 → ... → 1024)
let mut v = Vec::new();
for i in 0..1000 { v.push(i); }

// Хорошо: ровно одна аллокация
let mut v = Vec::with_capacity(1000);
for i in 0..1000 { v.push(i); }
```

Это особенно критично для больших векторов и горячих путей.

## `shrink_to_fit` / `shrink_to`

- `shrink_to_fit()` — пытается ужать `cap` до `len`. Может ничего не сделать, если аллокатор не поддерживает ужатие или это невыгодно.
- `shrink_to(min_cap)` — ужимает до `max(len, min_cap)`. Полезно, если вы знаете, что вектор ещё немного вырастет, но не до текущего `cap`.

```rust
v.shrink_to_fit();      // cap → len (если получится)
v.shrink_to(600);       // cap → max(len, 600)
```

Когда это имеет смысл: вектор **больше не будет расти** (или вырастет незначительно), а память нужна для других целей.

## Паттерн переиспользования буфера: `clear`

Если вектор используется многократно (например, буфер парсинга в цикле), **не создавайте его заново** — очищайте:

```rust
let mut buf = Vec::with_capacity(4096);

loop {
    buf.clear();          // len = 0, cap сохраняется!
    read_into(&mut buf);  // заполняем снова — без реаллокаций
    process(&buf);
}
```

`clear()` обнуляет `len`, но **не трогает `cap`** и не освобождает память. Это даёт нулевые аллокации на итерациях.

## Шпаргалка

| Метод | Что делает с `cap` | Что делает с `len` |
|-------|---------------------|---------------------|
| `with_capacity(n)` | = n | = 0 |
| `push` при `len == cap` | ×2 (реаллокация) | +1 |
| `clear()` | не меняет | = 0 |
| `shrink_to_fit()` | → len (best-effort) | не меняет |
| `shrink_to(n)` | → max(len, n) | не меняет |
| `reserve(n)` | ≥ len + n | не меняет |
| `truncate(n)` | не меняет | min(len, n) |

## Практические рекомендации

1. **Знаете размер** → `with_capacity`.
2. **Не знаете, но примерно** → `reserve` перед массовой вставкой.
3. **Переиспользуете буфер** → `clear()`, не пересоздавайте.
4. **Вектор больше не растёт** → `shrink_to_fit()` / `shrink_to(n)`.
5. **Не полагайтесь на конкретный коэффициент роста** — он не гарантирован контрактом.

## Резюме

- `Vec` = `(ptr, len, cap)`; `len ≤ cap` всегда.
- Рост при переполнении — реаллокация с копированием; амортизированно O(1) на `push` за счёт геометрического роста.
- `with_capacity` устраняет реаллокации, `clear` — переиспользует память, `shrink_to*` — освобождает лишнее.
- `shrink_to(n)` ужимает до `max(len, n)` — именно поэтому в вашем примере получилось `600`, а не `500`.
